# Web interface

Status: in progress. Implemented: the frame of every page, texts in two languages, static files, error pages (U1–U8); logging in and who may see what (U9–U18); the reading screen without a script (U19–U31); the script, keys and their page (U32–U40); subscriptions, categories and labels (U41–U52); import and export (U53–U54); settings of a user and administration (U55–U66). The rest of the interface is added step by step, see `plan.md`.
Sources: user requests of 2026-10-06 (an interface of freshgo's own, usable from the keyboard alone, with everything the web interface of FreshRSS can do, in English and Russian) and the decisions recorded in `plan.md`; FreshRSS at commit `219eaf58` for what the settings carried over by the import mean.

## Purpose and scope

`internal/web` is the web interface: pages rendered by the server, on which every action is a link or a form. It is freshgo's own; it shares neither markup, addresses, scripts, themes nor translations with the interface of FreshRSS.

Out of scope: the frontend of FreshRSS, PHP extensions, languages other than English and Russian.

## Requirements

- U1. Whatever path no other part of the server owns (`/accounts/`, `/reader/`, `/api/greader.php`, `/api/misc.php`, `/favicon/`, `/websub/`) belongs to the interface. A path it has no page for is answered with an HTML page and status 404, a method a page does not take with 405.
- U2. Every page has the same frame: a link to the content as the first thing `Tab` reaches, the name of the installation, the main menu with the current section marked `aria-current="page"`, a live region for messages (`#messages`, `role="status"`), and the content in `main#content`, which can take focus.
- U3. The language of a page is the best match among, in this order, what the browser asks for (`Accept-Language`) and the language of the installation (`language` of the system settings); English when neither is a language of the interface. A language only related to one of ours is not a match. `<html lang>` says which was chosen.
- U4. The interface speaks English and Russian. Every text exists in both, takes the same values in both, and a text that depends on a number has every plural form its language tells apart. A text missing in a language is shown in English.
- U5. Pages are sent with `Content-Security-Policy` that lets scripts and styles come from the server only (no inline code), while pictures, sound and frames of entries may come from anywhere; with `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin` and `Cache-Control: no-store`.
- U6. The stylesheet and the script are built into the binary and served under `/static/`. Pages link them by an address that carries a digest of the file; asked for by that address a file may be cached for good, asked for otherwise it is revalidated.
- U7. When the public address of the server (`-base-url`) has a path, every link starts with it; requests are expected without it, as a reverse proxy that strips the path sends them.
- U8. The name shown as the installation's is `title` of the system settings. `/about` shows the version and the address API clients connect to. The start page `/` is the reading screen.

- U9. How users are told apart is `auth_type` of the system settings:
  - `form`: by a login with name and password;
  - `http_auth`: by the reverse proxy in front of the server, which names the user in `Remote-User` or `X-WebAuth-User`. The header counts only when the request comes from an address in `-trusted-proxies` (`$FRESHGO_TRUSTED_PROXIES`; this machine by default), names one user, and the name can be a user name. A name nobody has yet becomes a user without passwords when `http_auth_auto_register` is on;
  - `none`: everybody is the default user.
- U10. `POST /login` takes `username`, `password`, `remember` and `next`. The password is checked against the bcrypt hash in the user's setting `passwordHash`, which import carries over, so the web password of FreshRSS keeps working. A wrong password, an unknown or malformed name, a disabled user (`enabled: false`) and a user without a web password are refused alike: status 401, one message, the name kept in the form, no cookie, and the same work done, so that neither the answer nor the time it takes tells which names exist. A name without a usable hash is checked against a decoy as costly as the hash of the default user. The body of a login request is read up to 16 KiB.
- U11. After five failed logins in a row for a name from an address, further ones from there are answered with 429 and `Retry-After` without looking at the password: for 30 seconds, then twice as long after every further failure, up to 15 minutes. Attempts are counted before the password is looked at, so attempts made at once count like attempts made in a row. A login that works, or 15 quiet minutes, clears the count. The address is that of the connection; when the connection comes from a trusted proxy, it is the last address in `X-Forwarded-For`, which is the one the proxy added. A name no user can have is refused without being counted.
- U12. A login is a random secret in the cookie `freshgo_session` (`HttpOnly`, `SameSite=Lax`, `Secure` when the browser reaches the server over HTTPS, for the public path of the interface) and its SHA-256 in the database. It lasts 24 hours after its last use; with `remember`, for `limits.cookie_duration` (90 days by default) after its last use, and the cookie then outlives the browser. Logins survive a restart of the server. `POST /logout` ends the login. A user who is disabled or deleted is out at once.
- U13. After logging in the visitor lands on `next` if it is a path of the interface, on the start page otherwise; never on another site.
- U14. A request that is not a GET or HEAD and comes from another site (`Sec-Fetch-Site`, or an `Origin` that is neither the server's nor the public address) is answered with 403 and changes nothing.
- U15. A page is for everybody, for readers, or for users. Readers are users and, when `allow_anonymous` is on, visitors who are not logged in: they read what the default user reads and can change nothing. A visitor who asks for a page that is not for them is sent to `/login?next=<the page>` when logging in is possible, and gets 403 otherwise; a request that changes something gets 403.
- U16. An administrator is the default user of the installation (`default_user`) and every user with the setting `is_admin`.
- U17. A user's pages are in their language (`language`, when it is a language of the interface) and colours (`darkMode`: `no` is light, `dark` is dark, anything else follows the system). An anonymous visitor reads in the language of their browser.
- U18. From the command line: `freshgo user create` gives the user one password for the web interface and for API clients, `-admin` makes them an administrator, and the first user of an installation becomes its default user. `freshgo user passwd` changes both passwords and ends the user's logins.

The reading screen, for readers (U15); what changes something is for users.

- U19. Streams of entries and their addresses: `/` and `/all`, the entries of the feeds shown in the main stream (priority 10 and above); `/starred`, the starred entries of every feed; `/feeds/<id>`, a feed whatever its priority; `/categories/<id>`, the feeds of a category shown in categories (priority 0 and above); `/labels/<id>`, the entries with a label. A feed, category or label the user does not have is 404.
- U20. Beside the stream stands the tree of what there is to read: the three streams of the interface, the categories with their feeds, the labels, each with its number of unread entries, counted over the same feeds its stream lists; the current one is marked `aria-current="page"`, a feed whose last refresh failed is marked. While only unread entries are listed and `hide_read_feeds` is not off, feeds without unread entries are left out, the current one excepted.
- U21. `state` narrows a stream to `unread`, `all`, `starred` or `unread-or-starred` entries. Without it the state follows the user's `default_view`: `all`; `unread`; `unread_or_favorite`; otherwise (`adaptive`, the default) unread entries while the stream has any, all when it has none. `/all` lists all, and with `show_fav_unread` so do `/starred` and the labels.
- U22. `sort` is `added` (the time an entry was received), `published`, `title`, `feed` or `random`; `order` is `desc` or `asc`. Without them the order is that of the feed or the category when its attributes name one (`defaultSort`, `defaultOrder`), else that of the user (`sort`, `sort_order`); the names of FreshRSS `id`, `date`, `title`, `f.name` and `rand` are understood, any other (`c.name`, `lastUserModified`, `length`, `link`) means `added`, for a feed too: its order is not replaced by that of the user. A random order is the shuffle `seed` picks (`storage.md`, S32); a page asked for without a seed picks one and names it in every address it gives out, the one actions come back to included, so that a shuffle lasts through its pages and through what the reader does on them. Links to states and to other streams keep the parameters the reader gave; a parameter with a value the interface does not know is passed over.
- U23. A page lists `posts_per_page` entries (20 when unset or not from 1 to 500) and links to the next one (`rel="next"`, parameter `after`) while there is one; pages follow each other as `storage.md`, S32, says. An `after` no page gave out is 404.
- U24. `q` is a search in the language of `search.md`, read with labels (Q15) and with the saved searches of the user (`queries`), dates in the user's time zone (`timezone`). The stream then lists what the search finds among its entries in the state shown (`storage.md`, S33). A search that cannot be read is answered with 400, a message marked `role="alert"` that says what is wrong, and no entries. The tree drops the search, the other links keep it.
- U25. An entry is listed as an `article` with its title as a heading inside the `summary` of a `details` element, which opens the entry in place without a script; with `display_posts` entries are listed open. An open entry and the page of an entry, `/entries/<id>`, show the title, the feed, the authors, the date in the user's time zone (the time the entry was received when it has no date), the text, the enclosures the text does not show already (pictures, players for sound and video, links for the rest), the tags of the feed and the labels. An entry of another user is 404.
- U26. The text of an entry is cleaned by the sanitizer of feed content once more when it is shown: an import brings entries FreshRSS cleaned, and not all of them well (`guid.md`). The link of an entry and its enclosures are shown only with an `http` or `https` address.
- U27. Handlers of `EntryBeforeDisplay` see every entry about to be shown; one they drop is left out of the list and has no page.
- U28. `POST /entries/<id>/read` (`read` 1 or 0) and `POST /entries/<id>/star` (`starred` 1 or 0) change the state of an entry, stamp the change (`storage.md`, S20) and call `EntriesRead`, when the state changed, and `EntriesFavorite`. `POST /entries/<id>/labels` gives the entry exactly the labels ticked (`label`, repeated) and the one named in `new`, which is created unless a label has the name already, be it one another request made at the same moment; a name a category has, or one longer than 191 characters, creates nothing and says so. Each sends the reader back to `next`, a path of the interface, at the entry (`#e<id>`).
- U29. `POST /read-all` marks read the unread entries of a stream (`stream`, its address) in the state and search the page showed (`state`, `q`) that were there when the page was made (`before`, an entry identifier, never later than now); with `older` `day` or `week`, only those received more than 24 hours or 7 days ago. The next page says how many entries it was. Handlers of `EntriesRead` are not called, as for `mark-all-as-read` of the API.
- U30. What an action has to say is shown once, in the live region of the page the reader lands on; it travels in the cookie `freshgo_notice` as the key of a text and a number, never as text.
- U31. A request with a parameter in its address, or a field in the form of an action, that is not text (bytes that are not UTF-8, or a NUL, which PostgreSQL does not keep) is answered with 400 and changes nothing.
- A look at a page changes nothing: opening an entry does not mark it read without a script. Marking on opening (`mark_when.article`) comes with the script (U37).

The script and the keys. Everything above works without the script; `/static/app.js` makes it quicker.

- U32. Every page loads the script and hands it, in `data-config` of `body`, what it needs as JSON: the keys (`keys`, a binding to the name of its action), whether keys pressed alone are on (`singleKeys`), the actions with their names in the language of the reader and their keys (`actions`), its texts (`texts`), addresses (`urls`), and `markOnOpen` and `autoLoad` (U37, U39). The script has no text and no address of its own.
- U33. Actions and their keys by default: `next` j and `prev` k open the next and the previous entry and close the one they opened before; `next-unread` h; `skip-next` n and `skip-prev` p move without opening; `toggle` o; `page` Space scrolls an open entry that does not end in the window, else opens the next one; `original` v opens the link of the entry in a new tab; `read` m; `star` s; `labels` l; `mark-all` A; `more` (no key) brings the next page; `refresh` r has the feeds fetched (U50); `search` /; `next-node` J, `prev-node` K and `unread-node` U go to the next stream of the tree, the previous one, the next one with unread entries; `tree` t folds and unfolds the tree; `go-unread` g u, `go-all` g a, `go-starred` g s, `go-subscriptions` g f, `go-keys` g k; `add-feed` + opens the page that adds a feed; `palette` :; `help` ?. Three keys are not bindings and always work: Enter opens and closes the entry in focus, Escape leaves a dialog, a field or a menu, Ctrl+K (and Meta+K) opens the palette.
- U34. A binding is one key or two pressed one after the other within 1.5 s, written with a space between them. A key is a character as the keyboard gives it with Shift (`j`, `J`, `?`) or a named key (`Space`, `Home`, `End`, `PageUp`, `PageDown`, the four `Arrow…`, `Backspace`, `Delete`, `Insert`, `F1`–`F12`; `Shift+` may precede a named key), with `Ctrl+`, `Alt+`, `Meta+` before it in that order; names are read in any case, a character after a modifier is lower case. A key does one action, and the first key of two none alone. The key of an action is the one in the setting `keys` of the user (an object, action to binding, empty for no key); without that setting, the one the user had in FreshRSS (`shortcuts`: `next_entry`, `prev_entry`, `next_unread_entry`, `skip_next_entry`, `skip_prev_entry`, `collapse_entry` for `toggle`, `go_website` for `original`, `mark_read`, `mark_favorite`, `mylabels`, `load_more`, `actualize` for `refresh`, `focus_search`, `toggle_aside` for `tree`, `help`); else the default one unless another action has it, which leaves the action without a key. `first_entry`, `last_entry`, `auto_share`, `user_filter`, `close_menus` and the three views of FreshRSS have no action here.
- U35. Keys do nothing while the focus is in a field or a dialog is open, Space presses the button, link or summary it is on, and a key of a layout without the characters of the bindings (Cyrillic, Greek) counts as the character its place gives on a US keyboard. With `keys_single_off` set, bindings made only of characters and Space pressed without Ctrl, Alt or Meta do nothing (WCAG 2.1.4); their actions stay in the palette.
- U36. `/settings/keys`, for users who are logged in, lists every action with a field for its key and the default one, and a checkbox for keys pressed alone. `POST` stores what the form gives (`key-<action>`, `single`) as `keys` and `keys_single_off`, or with `reset` removes both. A binding that cannot be read, or one that another action has, alone or as its first key, stores nothing: 400, the form as it was sent, the fields marked `aria-invalid` with what is wrong.
- U37. Keys act on one entry, the current one: the one a key moved to, or the one the focus is in; it has the focus after every action on it. An entry the reader opens, by a key, by Enter or by its summary, is marked read unless `mark_when.article` is `false` or the reader is a visitor. The script sends the forms of an entry with `X-Fragment: entry`: the answer is then 200 with the entry as a stream lists it (`article`) in place of the redirect, and the notice, if any, in `X-Notice`, encoded as a path segment, in place of the cookie. Actions on entries are sent one after the other, so that the page shows what the last one left.
- U38. A stream asked for with `X-Fragment: tree` is answered with its tree alone. The script asks for it after every action on an entry and every two minutes while the page is visible, and keeps the focus and the fold of the tree. On a screen at most 48rem wide the script folds the tree.
- U39. With the script the next page is appended to the list when its link comes within 600 px of the window, unless `auto_load_more` is `false`, and when `next` and its like run out of entries; an entry already listed is not added twice. The list is a `feed` and is `aria-busy` meanwhile.
- U40. The palette, the help, the labels of an entry and the question before "mark all as read" are `dialog` elements shown as modals: the focus stays inside, Escape closes them, the focus goes back to where it was. The palette is a `combobox` over a `listbox` of the actions and of the places `GET /palette` lists as JSON (`name`, `url`, `kind`): the three streams, the categories, feeds and labels of the user, the pages of the interface. What is typed picks the entries that have its characters in that order, the closest matches first; Enter runs the first or the one the arrows chose. The labels are the form of the page of the entry, sent as U37 says.

Subscriptions, for users who are logged in. Every form answers with a redirect to the page it belongs to and a notice (U30); a form that cannot be stored as it is answers with 400, the page as it was sent and what is wrong marked `role="alert"`.

- U41. `/subscriptions` lists the categories of the user with their feeds, and the labels; each name leads to its settings. Categories with a place (`position` of their attributes) come first, lowest first, the others after them by identifier; the tree of the reading screen and the palette follow the same order. A feed whose last refresh failed and a muted one are marked, a category that mirrors an OPML document too.
- U42. `/subscriptions/add` adds a feed: `POST /subscriptions/feeds` takes `url` (of a feed, or of a page that announces one), `category`, `kind` and `http_user` with `http_password`, and subscribes through `Refresher.AddFeed` (`refresh.md`, F28, F32). The reader lands on the settings of the new feed. An address that is none, a feed the user has already, a feed an extension refuses, an address that does not answer with a feed, and one feed too many for `limits.max_feeds` are told apart in what the page says. `?url=` and `?category=` fill the form in.
- U43. `/subscriptions/feeds/<id>` shows every setting of a feed and `POST` stores them, written into the feed as it is at that moment under its lock, so that a refresh going on loses nothing. The fields and what they store:
  - `name`, `url` (as `Refresher.AddFeed` spells it), `website` (an `http` or `https` address, else none), `description`, `category`, `priority` (20, 10, 0, -5, -10; the reading screen shows the last two alike, U19), `ttl` in seconds (0 for the period of the user) and `mute`, which stores the period below zero, that of the user when the feed has none; `kind` (0, 2, 10, 15, 25, 30, 35). A category, a priority or a kind there is not is passed over;
  - `http_user`, `http_password`: an empty password keeps the one there is while the user name stays, no user name removes both; the page never shows the password;
  - `path_entries`, and in the attributes `path_entries_filter`, `path_entries_conditions` (one search a line), `content_action` (`prepend`, `append`; replacing is not stored);
  - `filters_read`: the searches whose matches are marked read, one a line, kept in `filters` beside the other actions of the same searches;
  - retention (`archiving`): with `keep_own`, an object of `keep_period` (an ISO 8601 duration made of `keep_period_count` and `keep_period_unit`, or `false`; `P3M` when switched on without a count), `keep_max` (a number, 200 when switched on without one, or `false`), `keep_min`, `keep_favourites`, `keep_labels`, `keep_unreads`; without `keep_own` the key is removed and the level above decides;
  - `read_upon_gone`, `read_upon_reception`, `mark_updated_article_unread`, `ssl_verify`: `1`, `0`, or empty for the level above, which removes the key; `keep_max_n_unread` and `timeout` (a number, or removed); `read_when_same_title_in_feed` (a number, `false` for 0, removed when empty);
  - `xpath-<field>` into `xpath` for the kinds 10 and 15, `json-<field>` into `json_dotnotation` and `xpath_to_json` into `xPathToJson` for the kinds 30 and 35, the fields being `item`, `itemTitle`, `itemContent`, `itemUri`, `itemAuthor`, `itemTimestamp`, `itemTimeFormat`, `itemThumbnail`, `itemCategories`, `itemUid`, and `feedTitle` for JSON; a set without a value is removed, the settings of the other kinds are left alone;
  - the request, in `curl_params` under the numbers of `CURLOPT_*` that `fetch.FeedParams` reads: `proxy_type` (0, 2, 5, 7, and the SOCKS4 kinds 4 and 6 for feeds that came with them, which fail until it is changed) with `proxy`, `user_agent`, `cookie`, `cookie_file`, `headers` (one a line), `method` `POST` with `post_fields` (and `Content-Type: application/json` when the body is JSON and no header says otherwise), `redirects` (the limit, with following switched on, or 0 for no redirect at all; empty removes both keys). Keys the form has no field for stay; the whole is removed when nothing is left;
  - `unicity` (`unicityCriteria`, removed for `id`; `hasBadGuids` goes) and `unicity_forced`; `default_sort` (`id`, `date`, `title`, `f.name`, `rand`) and `default_order` (`ASC`, `DESC`), removed when empty.
  Attributes the form does not know stay as they are. `clear_cache`, `show_unread_count` and `display_enclosures` of FreshRSS are among them: freshgo neither shows nor uses them.
- U44. When what a feed is fetched and read by changes — its address, kind, credentials, selector, or one of the attributes `xpath`, `json_dotnotation`, `xPathToJson`, `curl_params`, `ssl_verify`, `timeout`, `unicityCriteria`, `unicityCriteriaForced`, `path_entries_conditions`, `path_entries_filter`, `content_action` — the stored validators are dropped, so that the next refresh reads the document whether or not the server calls it unchanged. Any other change keeps them.
- U45. The form of a feed is `multipart/form-data` and may bring a picture (`icon`, up to 1 MiB, an image as `favicon.ImageType` tells): it becomes the icon of the feed (`storage.md`, S12; attribute `customFavicon`), served under the hash of the custom icon. `icon_reset` removes it and the attribute. A file that is no picture, or too large, stores nothing of the form. The body of a form of settings is read up to 4 MiB.
- U46. `POST /subscriptions/feeds/<id>/preview` takes the same form, stores nothing, and shows the page as the form has it with what the selector and the filter of the form take from the page of the newest entry of the feed (`Refresher.PreviewArticle`), or why there is nothing to show: no selector, no entry with a link, a page or a selector that cannot be read, a selector that matches nothing.
- U47. Actions on a feed, each a form of its page: `/refresh` fetches it now, `/reload` fetches it anew (`refresh.md`, F33), `/truncate` deletes its entries, `/delete` unsubscribes. A feed that does not answer is not an error of the server: the notice says so and the page says since when the feed fails. Deleting asks first without a script: the button is inside a `details` element.
- U48. `POST /subscriptions/categories` (`name`) creates a category, after those that have a place when any has; the name is trimmed, must not be empty, longer than 191 characters or that of a category or a label, and `limits.max_categories` bounds their number. `/subscriptions/categories/<id>` shows and stores `name`, `position` (a number, or none), `opml_url` (U49), `filters_read`, retention and the default order as for a feed, and `read_when_same_title_in_category` and `read_when_same_guid_in_category` (a number each, 0 for every entry of the category, removed when switched off). The default category keeps its name. `/delete` removes a category, whose feeds go to the default one, which itself cannot be deleted; `/empty` unsubscribes from every feed of the category.
- U49. A category with `opml_url` is of kind 2 and takes its feeds from the OPML document at that address (`refresh.md`, F34); without the address it is a plain category again. `/subscriptions/categories/<id>/opml` reads the document now and says what came of it.
- U50. `POST /refresh` (`stream`, `next`) fetches the feed whose stream it names whatever its period, and for any other stream the feeds of the user that are due (`Refresher.RefreshUser`); the next page says how many entries are new, or that a refresh is going on already. The reading screen has the form for users, and for visitors when `allow_anonymous_refresh` is on; without it a visitor gets 403. The action `refresh` sends this form. A stream of a feed, a category or a label links to its settings.
- U51. `POST /subscriptions/labels` (`name`) creates a label under the rules of U48 for names. `/subscriptions/labels/<id>` shows and stores `name` and `filters_label`, the searches whose matches get the label on arrival (`search.md`, Q13); `/delete` removes the label from every entry and deletes it.
- U52. `/subscriptions/problems` lists the feeds whose last refresh failed, with the day it did, the muted ones, and those that are not muted and whose newest entry is older than 30 days, the longest silent first. The palette offers, beside the streams, the settings of every category, feed and label and the pages of subscriptions.
- U53. `/subscriptions/transfer` has the two forms. `POST /subscriptions/import` takes one file (`file`, up to 64 MiB; a larger one is 413) and hands it to `transfer.Import` (`transfer.md`, T4–T8) with the limits of the installation; the next page says how many feeds and entries were added or rewritten, and whether something was left out. No file, a name that does not say what the file holds, and a file that is not what its name says are 400 with what is wrong.
- U54. `POST /subscriptions/export` answers with a file to keep: `opml` the subscriptions (`feeds_<day>.opml.xml`), `starred` and `labelled` the starred entries, those with a label, or with both the entries that are either, in one document (`starred_<day>.json`), `feed` (repeated) the entries of feeds of the user (`feed_<day>_<category>_<feed>.json`; a feed there is not is passed over). One file goes out as it is, several as `freshgo_<user>_<day>_export.zip`; nothing chosen is 400. The day is that of the user's time zone.

Settings of a user, for users who are logged in; the main menu leads there, and every page of the section names the others. A form stores its fields under the names FreshRSS has for them in the settings of the user and leaves every other setting alone; one that cannot be stored answers with 400 and the form as it was sent.

- U55. `/settings/display`: `language` (a language of the interface), `timezone` (a name of the tz database, or empty for the zone of the server; one there is not is refused), `darkMode` (`auto`, `no`, `dark`), `content_width` (`thin`, `medium`, `large`, `no_limit`: how wide a page and the text of an entry get, as `data-width` of `html`), and what the row of an entry in a list names: its feed (`topline_website`, `full` or `none`) and its date (`topline_date`).
- U56. `/settings/reading`: `posts_per_page` (1 to 500), `default_view` (`adaptive`, `unread`, `all`, `unread_or_favorite`), `sort` and `sort_order`, `display_posts`, `auto_load_more`, `hide_read_feeds`, `show_fav_unread`, `mark_updated_article_unread`; of `mark_when` the keys `article`, `reception`, `gone`, `max_n_unread` (a number, or `false`) and `same_title_in_feed` (a number, or `false`), its other keys staying as FreshRSS left them; and the searches whose matches are marked read and starred, in `filters`. The reading screen, the script and the refresh go by what is stored (U21–U23, U37, U39; `refresh.md`, F18–F24).
- U57. `/settings/archiving`: `ttl_default` and the rules of keeping entries (`archiving`, as U43 has them, without a level above). `POST /settings/archiving/purge` applies the rules of the user, the categories and the feeds now (`Refresher.PurgeUser`) and says how many entries went.
- U58. `/settings/privacy`: `send_referrer_allowlist`, host names one a line. A frame an entry embeds from one of these hosts gets `referrerpolicy="strict-origin-when-cross-origin"`; everything else an entry loads is told nothing (U5).
- U59. `/settings/profile`: `mail_login` (an address, or none) and `token` (up to 191 visible ASCII characters). `POST /settings/profile/password` gives another web password (`new`, `again`: 7 characters to 72 bytes, both alike) to whoever types the current one (`password`) when there is one, and ends every other login of the user. `…/api-password` sets the password of API clients (`new`), or with an empty one removes it. `…/delete` deletes the account with everything in it after the password is typed; the default user of the installation cannot. Guesses of the current password are counted and paused like failed logins (U11): a wrong one is 403, one that has to wait 429.
- U60. `/log` lists the warnings and errors the server logged about the user (`storage.md`, S37), newest first, 100 a page, narrowed by `q` to the records that have the text; `POST /log/clear` deletes them. With `all` an administrator gets, and clears, the records about everybody, after typing the password again when the login is old (U61); anybody else gets their own, and 403 for clearing. A record is about a user when the server logged it with the name of a user it had made sure of: a request that only claims a name leaves none.

Administration, for administrators (U16); anybody else gets 403.

- U61. An administrator whose login is older than `reauth_time` (20 minutes by default; 0 for never) is sent from a page of the administration to `/reauth?next=<the page>`, and from a form of it, which is then not carried out, to `/reauth?next=/admin/users`. `POST /reauth` takes the password (`password`, guarded as in U59) and makes the login fresh. Users who are told apart without a login have no password to type and are not asked.
- U62. `/admin/users` lists the users with their role, whether they are kept out, and their numbers of feeds and entries, and adds a user: `name` (a user name), `new` and `again` (as U59), `admin`; the password is that of the web interface and of API clients alike, as `freshgo user create` sets it.
- U63. `/admin/users/<name>` acts on a user by `action`: `password` (`new`, `again`; both passwords, and the logins of the user end), `disable` (and the logins end) and `enable`, `promote` and `demote`, `delete` (with the journal about the user). `disable`, `demote` and `delete` are refused for the administrator's own account and for the default user.
- U64. `/admin/system`: `title`, `language`, `limits.max_feeds`, `max_categories` and `max_registrations`, `limits.cookie_duration` (in days), `reauth_time` (in minutes), `closed_registration_message`; numbers below zero store nothing. The page shows the internal addresses feeds may be fetched from, which are a flag of the server (`-fetch-allowlist`) and not a setting.
- U65. `/admin/authentication`: `auth_type`, `http_auth_auto_register`, `allow_anonymous`, `allow_anonymous_refresh`, `api_enabled`. Logging in by password is not switched on by an administrator who has no web password, and the reverse proxy or no login at all only when the request that asks for it would itself be taken for an administrator that way: the proxy names the administrator on it, the default user exists.
- U66. With `api_enabled` off the Google Reader API answers every request with 503 (`greader-api.md`, A37). `limits.max_feeds` and `limits.max_categories` hold for what API clients add, OPML included.

## Decisions

- **Pages are rendered by the server** with `html/template`; there is no build step and no framework. Rejected: a single-page application over a JSON API, which doubles the code and does not work without a script.
- **Texts are JSON files, one per language, with CLDR plural categories**, chosen by `golang.org/x/text`. The translations of FreshRSS are not used: the interface has texts of its own.
- **Static files are told apart by a digest in the query string**, not in the file name: the files keep their names in the source tree and no step renames them.
- **The password is sent by the login form as it is**, protected by TLS, and compared with the stored hash. The challenge of FreshRSS, where the browser hashes the password with bcrypt, is not reproduced: it exists for logins without HTTPS and needs a script.
- **Logins are rows in the database**, not signed cookies: they can be ended from the server, which a change of the password does.
- **Requests from other sites are turned down by `http.CrossOriginProtection`** of the standard library; forms carry no token.
- **Failed logins are counted per name and address, in memory.** Counting per name alone would let anybody lock a user out; a restart of the server clears the counts.
- **An entry opens in place by `details`**, the element browsers open and close from the keyboard themselves; the script of the next step builds on it instead of replacing it.
- **Opening an entry does not mark it read without a script**: that would be a GET that changes something, or a button where a link belongs. The form next to the entry does it.
- **"Mark as read" is bounded by the moment the page was made**, not by the entries it listed: an entry identifier is the time the entry was received, so the moment is a bound every entry the reader could have seen is under.
- **The script gets parts of pages, not data**: the same templates render an entry and the tree for a page and for the script, told apart by `X-Fragment`. Rejected: JSON for the script to render, a second rendering of the same things.
- **The tree is a `nav` of lists of links, not an ARIA `tree`**: the role would replace the links by tree items that Tab passes over and screen readers read in another mode, for a list one level deep. J, K and U walk it; `aria-current` marks the stream shown.
- **Dialogs are the `dialog` element**, which keeps the focus inside, closes on Escape and gives the focus back by itself.
- **A key is told by the character it gives** (`KeyboardEvent.key`), so that `?` is `?` on every layout, and by its place on the keyboard only when the layout has no such characters.
- **Sharing an entry has no action** before the page of integrations.
- **A form of settings writes its fields into what is stored and leaves the rest alone**, feeds under their lock: a refresh that is going on, and settings freshgo does not show, lose nothing.
- **Refreshing from a page waits for the answer** instead of running behind the page: the notice can then say what came of it, and a run that is going on is not waited for.
- **Deleting asks first by a `details` element** that holds the button, not by a script: the question is there without one.
- **The feeds that need a look are one page**, which the statistics link to instead of having a list of silent feeds of their own.
- **The browser scenarios are Go tests behind the build tag `e2e`**, in the package of the interface, where they share the reference installation with the tests of the handlers. They are not part of `make test`: they need Chrome.
- **The password is asked for again before the pages of the administration, not before each of its forms**: a form that arrives too late is not carried out, and its page is where the administrator comes back to.
- **The journal is a table**, which a handler of `log/slog` fills with the warnings and errors that name a user; FreshRSS keeps a file per user. Records are written behind the back of whoever logs them, up to 256 waiting: a record is often logged inside a transaction, and a write from there would wait for it.
- **The internal addresses feeds may be fetched from stay a flag of the server**, like the rest of its network settings; the page of the system shows them.
