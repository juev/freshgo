# Import and export of entries

Status: implemented.
Sources: user requests of 2026-10-06 and requirement R10 of `plan.md`; issue #138 (import from Miniflux and Tiny Tiny RSS); the REST API of Miniflux, <https://miniflux.app/docs/api.html>; the JSON API of Tiny Tiny RSS, `api/index.php`, `classes/API.php`, `classes/RSSUtils.php` and `classes/Article.php` of tt-rss (the wiki reference at tt-rss.org/ApiReference is gone); `FreshRSS_Entry::toGReader` in its `freshrss` mode, `app/views/helpers/export/articles.phtml`, `FreshRSS_Export_Service` and `FreshRSS_importExport_Controller::importFile`, `importJson`, `addFeedJson`, `guessFileType` of FreshRSS at commit `219eaf58`.

## Purpose and scope

`internal/transfer` writes the entries of a user as the JSON documents FreshRSS exports, and reads such documents, those of Google Reader and of readers that write the same format, OPML documents, lists of addresses and ZIP archives of all of these. It also writes one account of another reader's server, read by a package for that server, into the account of a user (T9–T14); `internal/miniflux` reads Miniflux (T12) and `internal/ttrss` Tiny Tiny RSS (T15). The pages that use it are in `web.md`, U53–U54 and U113; OPML itself is `internal/opml` (`greader-api.md`).

Out of scope: the file of starred articles that Tiny Tiny RSS exports as XML and FreshRSS reads (the import from the server carries the starred articles of the account through the API instead); from Miniflux, the icons of feeds (a refresh fetches them again), the integrations of the account (Pocket, Linkding and the like), API keys, the rules for entries that have no counterpart in T12, and entries the account has deleted (`status` `removed`); from Tiny Tiny RSS, the icons of feeds, the tags of articles (a feed's own categories fill them), notes, published articles, attachments, plugins and what the API does not give (filters, logins of feeds, per-feed settings other than T15 lists).

## Requirements

- T1. A document is a JSON object: `id` (`user/<name>/state/org.freshrss/<kind>`, the kind being `starred` or `feed/<id>`), `title`, `author` (the name of the user) and `items`, the entries oldest first. Text is written as it is, not as the escapes JSON allows for `<`, `>` and `&`.
- T2. An item has `frss:id` (the identifier, as a text), `id` (`tag:google.com,2005:reader/item/` and the identifier as 16 hexadecimal digits), `crawlTimeMsec` and `timestampUsec` (the identifier is the time the entry was received), `published`, `title` and `author` (the authors joined by `; `) with `&`, `<`, `>` and `"` written as HTML entities, the way FreshRSS keeps and writes them, `canonical` and `alternate` (the link; `type` `text/html` in the second), `content.content` (the text as stored), `guid`, `origin` (`streamId` `feed/<id>`, `htmlUrl`, `title`, and `feedUrl`, the address of the feed without its credentials), `enclosure` (`href`, `type` or else the medium, `length`) and `categories`: `user/-/state/com.google/reading-list`; `…/org.freshrss/main` for a feed of priority 10 and above, with `…/important` from 20, `…/hidden` for -10 and below; `…/com.google/read` or `…/unread`; `…/starred`; `user/-/label/<name>` for every label; then the tags of the feed.
- T3. Handlers of `EntryBeforeDisplay` see every entry on its way into a document and may keep it out. A document for the public (`web.md`, U72) lists entries as a listing of the store orders and bounds them, and leaves the labels of the user out.
- T4. `Import` tells what a file holds by its name, as FreshRSS does: `.zip` an archive; `.txt` a list of feed addresses, one a line; a name with `opml`, or ending in `.xml`, an OPML document; `.json` a document of entries, a list of starred ones when the name has `starred` in it. Any other name is `ErrUnknownFile`. Of an archive, the files with such names are read, up to 1000 of them, 64 MiB each unpacked and 256 MiB together: past either bound the rest of the archive is not unpacked, however its files are listed, and the import is incomplete; subscriptions are taken in before entries. A file that is not what its name says is `ErrDocument` (`opml.ErrDocument` for OPML) when it is the only one, and otherwise leaves the import incomplete.
- T5. An item becomes an entry of the feed it names: `origin.feedUrl`, else `origin.streamId` after `feed/`, else `origin.htmlUrl`, each spelled as `Refresher.AddFeed` spells addresses and compared without credentials; an item that names none goes to the muted feed `http://import.localhost/import.xml`. A feed the user does not have is added without being fetched, with `origin.title` (or `Import`) for its name, `origin.htmlUrl` for its site and the category `origin.category` names, which is created when there is none; `FeedBeforeInsert` may refuse it. `Options.MaxFeeds` and `MaxCategories` bound what is added.
- T6. Of an item are read, with the NUL characters JSON can spell left out: `guid`, else `id`, as the identifier within the feed, trimmed and cut to 767 bytes as a refresh stores it (an item without one is passed over, the first of several with one identifier stands); `title` with the entities of T2 decoded (the link when there is none; none when it equals the identifier); `author` split at semicolons; the text from `content.content`, `summary.content` or a plain `content`, cleaned as the text of a feed is; the link from `alternate[0].href` or `url`, when it is an `http` or `https` address; the date from `published`, `timestampUsec` or `updated`, as Unix seconds, milliseconds, or a date written out, in the time zone of the user; `categories`: the states `read`, `unread` and `starred` and the labels of any user (`user/<anything>/…`), everything else the tags of the entry. An entry whose item says neither read nor unread is read when the user marks entries read on arrival (`mark_when.reception`). In a list of starred entries, an item without a label is starred without saying so.
- T7. An entry the feed does not have is added, after `EntryBeforeInsert` and `EntryBeforeAdd`, without a hash (`refresh.md`, F10), with identifiers in the order of the dates. One the feed has, by its identifier, gets the title, authors, text, link, date and tags of the item after `EntryBeforeInsert` and `EntryBeforeUpdate`; it becomes read or unread only when the item says so, starred when the item says so, and never loses its star. Labels are attached, and made when the user has none of that name; a name a category has gives no label and leaves the import incomplete.
- T8. One document is taken in within one transaction. The report counts the feeds added and the entries added and rewritten, and says when something was left out: a feed past the limit or refused, an item whose feed has no usable address, a label that could not be made, a part of an archive that was passed over.
- T9. `ImportRemote` takes a `Remote`: the names of the categories, the feeds (`RemoteFeed`) and the entries (`RemoteEntry`) of an account, with the warnings its reader made. A reader of a server (`miniflux.Read`) makes it with the network and writes nothing; `ImportRemote` writes it with the database and fetches nothing, so a reader that fails half way has changed nothing, and an error of the write leaves the account of the user as it was: all of it is one transaction.
- T10. Categories are made by name when the user has none of it, also those without feeds, up to `Options.MaxCategories`; past it a feed goes to the default category and the import is incomplete, with a warning. A feed the user has already, by its address without credentials, keeps its settings and takes the entries; a new one is added without being fetched, up to `Options.MaxFeeds`, and the feeds past the limit are named in one warning. An entry whose feed was not imported, and an entry with neither a link nor an identifier, is counted in one warning.
- T11. A feed added by `ImportRemote` has the name, site and category of the source, the priority of a feed in the main stream (`CategoryOnly`: of one shown in its category only), a muted period when the source has it disabled (`Muted`), the credentials as `user:password`, the user agent and the cookie as the request settings of a feed (`curl_params`), a CSS `Selector` for the full text or `Automatic` for the article found on its page, and its entries told by their links (`unicityCriteria` `link`, forced). The last is because the identifier a source keeps is not the one a refresh computes, while the link is: the next refresh finds the imported entries instead of adding them again. A feed the user has already, whose criteria are not `link`, is named in a warning: a refresh may add its imported entries once more.
- T12. Miniflux (`miniflux.Read`) is read through its REST API with the header `X-Auth-Token`: `/v1/me` first, so that a wrong token or address fails before the long part, then `/v1/categories`, `/v1/feeds` and `/v1/entries` with `status` `read` and `unread`, `order` `id`, `direction` `asc`, `limit` 100 and `after_entry_id` of the last entry seen, until a page is short; entries that do not come in increasing order of identifiers are an error. A feed becomes: `title`, `site_url`, `feed_url`, the category's `title`; `disabled` muted; `hide_globally` of the feed or of its category in its category only; `username` and `password` the credentials; `user_agent`, `cookie`; `crawler` with `scraper_rules` the selector, `crawler` alone the automatic article, no `crawler` neither (Miniflux applies its scraper rules only with the crawler). Warned about, with the feeds they are set on: `rewrite_rules`, `urlrewrite_rules`, `blocklist_rules`, `keeplist_rules` (the filter actions of freshgo mark entries and do not drop them, and the dialect of the expressions differs), `fetch_via_proxy` (the proxy of Miniflux is not the one of the installation), `allow_self_signed_certificates`. An entry becomes: `title`, `author`, `url` (also its identifier; the `hash` when it has none), `content` cleaned as the text of a feed is, `published_at`, read when `status` is `read`, starred when `starred`; `tags` become labels.
- T13. An entry the feed has already, by its identifier, gets the title, authors, text, link and date of the source and its read state, whichever it is, and its star when the source has it, and never loses its star; labels are attached and never taken off. So the import can be run again to catch up with the source without adding anything twice.
- T14. The report of `ImportRemote` counts the feeds added and the entries added and updated, says when something was left out, and carries the warnings. They are English texts made by the readers, shown as they are.
- T15. Tiny Tiny RSS (`ttrss.Read`) is read through its JSON API: a POST of a JSON object with `Content-Type: application/json` to `<address>/api/`, the operation in `op`, the session in `sid`. `login` (`user`, `password`) gives `session_id`; `LOGIN_ERROR` is `ErrLogin` and `API_DISABLED`, the answer of a user who has not turned the API on (Preferences, Enable API), is `ErrAPIDisabled`, so that the page and the command can tell them apart. The API answers 200 also to a refusal, with `status` 1 and `content.error`. Then `getCategories` with `include_empty`, once with `enable_nested` and once without: the API does not say which category sits inside which, but what the nested list lacks was nested; the virtual categories (id 0 and below) are not taken, and nested categories become top-level ones with one warning. `getFeeds` with `cat_id` -3 (every real feed; -4 adds virtual ones): `feed_url`, `title`, the category by `cat_id`; a negative `update_interval` (updates disabled) is a muted feed, a positive one is warned about with the feeds it is set on, since freshgo asks a feed as often as it publishes. The API gives no site address with a feed, so the first `site_url` of its headlines stands for it. `getHeadlines` with `feed_id` -4 (all articles), `view_mode` `all_articles`, `show_content`, `order_by` `date_reverse` (oldest first, so articles that arrive during the read land after the pages), `limit` 200 (the most the API gives) and `skip` of the articles seen, until an empty page: a page shorter than 200 is not the end, because older servers cap lower; a page with nothing new is an error. An article becomes: `title`, `author`, `link`, `content` (cleaned as the text of a feed is), `updated` the date, read when not `unread`, starred when `marked`, the captions of `labels` labels. Warned about once each, with the number of articles: `published` (shared in the public feed), `note`, `tags`. One warning, always: the filters and the logins of feeds are not given by the API. `logout` ends every read that got a session, also a failed or cancelled one. `getLabels` is not called: a label that is on no article has nothing to be attached to.
- T16. A reader stops with `ErrRemoteTooLarge` once the answers of the server for one account come to more than `MaxRemoteBytes` (256 MiB): the account is held in memory until it is written, and the server is one the user names, which could page without end. The transfer page says so; nothing is written.

## Decisions

- **The format is that of FreshRSS**, entities in titles included: a file freshgo writes can be read by FreshRSS and the other way round. Reading decodes the entities; FreshRSS encodes them once more when it reads its own export, which freshgo does not reproduce.
- **Every entry of a chosen feed is exported**, not the newest 50 as in FreshRSS: the bound there keeps a PHP request within its memory.
- **An import does not fetch anything.** Feeds it adds get their entries with the next refresh. An import from a server fetches the account only, never the feeds.
- **A source is read whole before anything is written.** The account sits in memory between the two: a transaction that waited for a server over the network would hold the lock of the database as long as the server takes. The price is memory proportional to the account; page by page reading into the database is the way out when accounts of a million entries show up.
- **The guard of the fetch client decides which servers can be reached.** The page for users (`web.md`, U113) reads through the client that fetches images, so the protection against internal addresses and `-fetch-allowlist` apply: a Miniflux at a private address must be on the allowlist, or users could make the server ask any address of its network. `freshgo import -from miniflux` is a command of the operator, who names the address themselves, and runs with the protection off; the proxy of the installation still applies.
- **Filters are not carried over.** The block and keep rules of Miniflux drop entries when they arrive; a filter action of freshgo marks them read or starred. Translating one into the other would change what the user sees, silently, so it is a warning.
- **Tiny Tiny RSS entries are told by their links.** The `guid` its API gives is `{"ver":2,"uid":<user>,"hash":"SHA1:<sha1 of the guid the feed gave>"}`: a hash with the id of the user inside, from which the identifier of the feed cannot be recovered, and not what a refresh of freshgo computes. The link is, so the feeds are set to unicity `link` (T11), as for Miniflux, and the next refresh finds the imported articles; the `guid` stands for the link of an article that has none.
- **A new source is a reader and a name for the page and the command.** The writing is `ImportRemote`; Tiny Tiny RSS plugs in by making a `Remote`.
